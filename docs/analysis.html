SplitEase — Codebase Deep Dive

A full-stack shared expense tracker · Next.js + Express + PostgreSQL

What it does

SplitEase is a Splitwise-style expense tracker. Users create groups, add members, record shared expenses, have them split equally, see real-time balances (who owes whom), and settle up with payments. It also has an activity feed, expense reactions (emojis), group summary charts, and a dashboard.

What's built

  • JWT auth (signup / login / me)
  • Groups + member roles (admin/member)
  • Expenses with equal-split engine
  • Balance calculation & settle payments
  • Activity feed + emoji reactions
  • Group summary with chart
  • Dashboard with totals

Equal-split engine

expense.service.js: distributes the cent-remainder fairly so every split sums exactly to the total. 
calculateEqualSplits(totalCents, count):
  base = floor(totalCents / count)
  rem  = totalCents - base*count
  for i in 0..count: share = i < rem ? base+1 : base   // first `rem` pay +1¢

Balance formula

balance.service.js: per member → 
balance = totalPaid - totalShare - paymentsReceived + paymentsMade
  > 0 → OWED   < 0 → OWES   = 0 → SETTLED

Observations & issues

1. Currency inconsistency (real bug)
expense.service.js:101 logs activity using "Rs." (rupees), but the whole frontend renders USD ($ / formatCurrency). Activity feeds will display "added Rs. 50 for pizza" next to "$50.00" UI.
2. README is stale
It claims "Milestone 0 — Repository Initialization" with the next step being an ERD, but the application is fully implemented and tested.
3. Client-only auth
JWT lives in localStorage; route protection happens client-side in layouts (ProtectedRoute / effect redirect). No httpOnly cookie / Next middleware-based protection.
4. Stubbed features
SocialLogin and forgot-password / reset-password UI exist, but there are no corresponding backend endpoints (no OAuth, no password-reset mail).
Strengths
Clean layered frontend, consistent design system, transactional backend with activity logging, 10 integration test suites, fair split math, typed API contract between frontend/backend.
